# H5-D18: which extension method a C# call reaches

The validation record of a fix that is **not merged, with its gate open.** The author's decisions are in
[decisions.md](../../decisions.md); the method is in [method.md](../method.md) and [judgment.md](../judgment.md).
Live outputs name the install's tenants, so snapshots are given by number.

## 1. The finding and the rule

A judgment after PR #27 traced one wrong edge: elsa's `x.GetInput<string>(item)`, in a lambda without a type, reached
`ActivityExtensions.GetInput(string)`, which has no type parameter. No code checked a call's type arguments. The fix
applies to a call that only the repo's extension methods can serve: its receiver's type is outside the repo, or
unknown when the call passes type arguments. It reaches 104 edges in the 15 C# repos of PR #27's protocol: 24 to an
extension block's method (elsa 20, smartstore 4) and 80 to an extension with a `this` parameter (elsa 45, radarr 18,
umbraco 9, smartstore 6, jellyfin 1, notifo 1).

1. **Type arguments.** A call written with type arguments reaches only a method that declares type parameters, its own
   or its extension block's.
2. **A receiver outside the repo.** When the type the receiver's chain ends in is outside the repo, the call reaches no
   extension whose `this` is a type of the repo. A `this` counts as a type of the repo only when C#'s scopes reach one
   from the extension's file, with as many type parameters as the `this` passes type arguments. A type outside the
   repo met before the chain's end (`_lazy.Value`) proves nothing.
3. **Dropping takes targets away.** An extension that may or may not take the receiver keeps the strategy `main` gives
   it, `-ambiguous` included. One whose `this` is the receiver's type, or takes any value, takes the strategy left and
   is a new target only when it is the only one.

**A follow-up outside H5-D18: the count of type arguments (C2-002).** At elsa's `MassTransitWorkflowDispatcherFeature.cs:26`
a call with two type arguments keeps the overload with one type parameter and does not reach the one with two. Part 1
checks that type parameters exist, not their count. To validate first, with a compiler on synthetic code: how C# 14
counts explicit type arguments on an extension block's method.

**Known limits of part 3:** a `this` of a predefined type (`this string`) has no name in the type facts, so it is
never known to take a value and dropping its overloads adds no target; a receiver of unknown type is never compatible
with an interface's `this`; overloads declared on one line share their facts' key; a compatible `this` is matched by
name without its type arguments.
