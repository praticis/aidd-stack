# What a count of the graph may not move the wrong way (docs/indexer/method.md §4.4, indexer/scripts/judgment/scorecard.py).
#
# One per line, `repo.strategy.confirmed :: >= N :: note` or `repo.strategy.contradicted :: <= N :: note`, over the typed edges
# (`receiver-type` and `inherited`, ambiguous or not) of a TS repo of the micro set, judged by TypeScript's checker
# (`checks/ts_checker.js`): `confirmed` edges agree with the checker, so a floor, and `contradicted` ones name another declaration
# of the repo than the checker does, so a ceiling. A count has no denominator and the graph is deterministic, so a count past its
# bound is a change of the graph, never noise. A line that starts with `#` is a comment.
#
# A bound is changed by editing its line in the diff of the change that moves it, under the `graph-change` label: lowering a floor
# or raising a ceiling is a number the author reads, and the label alone would free every change of the graph. A new repo or
# strategy gets a line: `scorecard.py RUN_DIR --rows DIR --write-floors` prints them.
